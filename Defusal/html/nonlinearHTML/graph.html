01 / UNDERSTAND

Model relationships, not just sequences.

A graph is a non-linear data structure consisting of vertices and edges. A vertex represents an object, while an edge represents a relationship between two objects.

For example, cities can be vertices and roads can be edges. Unlike an array or linked list, a graph does not require one fixed sequential order.

By the end, you should be able to:

  • Identify vertices, edges and neighboring vertices.
  • Distinguish directed, undirected and weighted graphs.
  • Read an adjacency list and adjacency matrix.
  • Trace BFS using a Queue.
  • Trace DFS using recursion or a Stack.

Vertex

A node such as city A, user B or computer C.

Edge

A connection between two vertices.

Neighbor

A vertex connected directly by an edge.

Path

A sequence of vertices joined by edges.

02 / TYPES

Direction and weight change the meaning.

Undirected Graph

Edge A—B can be followed from A to B and from B to A.

Directed Graph

Edge A→B allows movement from A to B. It does not automatically allow B→A.

Unweighted Graph

Every edge is treated equally. BFS can find a path with the fewest edges.

Weighted Graph

Each edge stores a cost such as distance, price or travel time.

Is every tree also a graph?

Yes. A tree is a connected graph with no cycles. Not every graph is a tree because graphs may have cycles, disconnected components or multiple paths.

03 / REPRESENTATION

Store edges using a matrix or lists.

Adjacency Matrix

A V × V table. matrix[i][j] is 1 when an edge exists and 0 otherwise.

  • Check an edge: O(1)
  • List all neighbors: O(V)
  • Storage: O(V²)

Adjacency List

Each vertex stores a list of its neighboring vertices.

  • List neighbors: O(degree)
  • Traversal: O(V + E)
  • Storage: O(V + E)

Which representation should be used?

An adjacency list is usually efficient for a sparse graph with relatively few edges. An adjacency matrix can be useful when the graph is dense or edge existence must be checked frequently.
